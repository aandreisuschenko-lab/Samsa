# AI Content Plan Agent — Задание №5 (мастер контент-план Digital)

Агент ведёт мастер контент-план за digital-менеджера: пересчитывает дедлайны по
правилам каждого типа кампании, находит конфликты и риски срыва, строит
интерактивный календарь и еженедельный дайджест.

## Быстрый старт

```bash
python run.py data/samsung-digital-content-plan-template.xlsx \
              --models data/samsung-creative-brief-template.xlsx \
              --today 2026-07-01
```

Никаких зависимостей, кроме `openpyxl` (`pip install openpyxl`). Для файла
следующего месяца меняется только путь ко входному Excel — код не трогаем.

| Флаг | Назначение |
|---|---|
| `--today YYYY-MM-DD` | дата расчёта; по умолчанию системная. Позволяет прогонять план «глазами менеджера» на любую дату |
| `--models <xlsx>` | файл креативного брифа из Задания №1 — источник приоритетных моделей для проверки покрытия |
| `--out <dir>` | папка результатов (по умолчанию `out/`) |

## Что на выходе

| Файл | Содержание |
|---|---|
| `out/content_plan_corrected.xlsx` | исходный план с исправленными дедлайнами — **формулами**, а не значениями. Меняете дату старта в колонке «Старт» — дедлайны пересчитываются прямо в Excel. Жёлтая заливка — исправленный дедлайн, оранжевая — дедлайн в прошлом, комментарий в колонке «Статус» — найденные проблемы |
| `out/calendar.html` | интерактивный Гант: окно продакшена, флайт, пины этапов Б/К/С, линия «сегодня», фильтры и сценарий «что если» |
| `out/checks_report.md` | отчёт проверок с приоритетами P1/P2/P3 + таблица «было → стало» по всем дедлайнам |
| `out/weekly_digest.md` | недельный дайджест: что горит, что делать на этой неделе, где дыры |
| `out/plan.json` | машиночитаемый срез для интеграций (напр. запуск генерации креативов из Задания №1) |

## Как считаются дедлайны

Правила **читаются из самого файла** (вкладка «2. Правила дедлайнов»), а не
захардкожены. Поменяется цикл продакшена — пайплайн подхватит новые сроки.

- Каждый этап отсчитывается назад от даты старта по правилу своего типа кампании
  (Промо-запуск / Always-on / Медийка / Retail support / Маркетплейс).
- Дедлайн, выпавший на выходной, переносится на предыдущий рабочий день.
  В Excel это формула `=WORKDAY(Старт − N + 1; −1)` — она возвращает сам день,
  если он рабочий, и предыдущую пятницу, если он выпал на субботу/воскресенье.
- Неизвестный тип кампании → берётся самый консервативный набор правил
  (чтобы агент не занизил сроки на новом типе).

### Найденная ошибка в исходном файле

В шаблоне все дедлайны посчитаны единым правилом −14 / −7 / −3. Расхождения
с правилами по типам агент выносит в отчёт отдельным блоком. Критичные:

- **C-06, C-09 (Медийка)** — брифу нужен −21 день, а стояло −14. Оба брифа
  оказываются просроченными, а видеопродакшен физически не успевает к старту.
- **C-03, C-08 (Маркетплейс)** и **C-10, C-12 (Always-on)** — цикл короче
  стандартного, дедлайны стояли раньше нужного (ложная срочность).
- **C-04, C-05, C-11 (Retail support)** — согласование −4 дня вместо −3.

## Проверки

| Код | Приоритет | Что ловит |
|---|---|---|
| `RULE_MISMATCH` | P1/P2 | дедлайны, посчитанные не по правилам своего типа |
| `OVERDUE` | P1 | дедлайн в прошлом при статусе ≠ Готово |
| `INFEASIBLE` | P1 | до старта меньше времени, чем требует цикл производства |
| `NO_CREATIVE` | P1 | старт менее чем через 7 дней, креатив не готов |
| `WEEK_OVERLOAD` | P2 | больше 4 запусков на неделю |
| `DEADLINE_CRUNCH` | P2 | больше 6 дедлайнов на ближайшие 7 дней |
| `MEDIA_NO_PERF` | P2 | медийка на модель без перформанс-поддержки |
| `MODEL_GAP` | P2 | модель из креативного брифа без кампаний в месяце |
| `DISTRIBUTOR_GAP` / `CHANNEL_UNKNOWN` | P3 | дистрибьютор без поддержки, канал вне матрицы |
| `BUDGET_BALANCE` | P3 | доля медийки выше порога |
| `NO_SALES_POINT` | P3 | модель без маркетплейса и дистрибьютора |

Пороги (4 запуска в неделю, 6 дедлайнов, 7 дней до старта, 40% медийки) тоже
вычитываются из вкладок «Трекинг» и «Правила дедлайнов».

## Сценарий «что если»

В `calendar.html` выберите кампанию и сдвиньте ползунок: дедлайны
пересчитываются в браузере по тем же правилам, пины перекрашиваются, видно,
уходит ли кампания из красной зоны. Пересчёт локальный — файл можно отправить
менеджеру одним вложением, ничего запускать не нужно.

## Допущения

1. **«+1 день на согласование с дистрибьютором».** В таблице правил этот день уже
   зашит в тип Retail support (−4 против −3 у промо). Для кампаний других типов,
   ведущих на дистрибьютора, агент добавляет его сам — иначе правило не работает.
2. **Дистрибьюторы** определяются как назначения из матрицы каналов за вычетом
   samsung.kz и маркетплейсов (Kaspi, Ozon).
3. **Перформанс-типы** для правила «медийка только с поддержкой»: Промо-запуск,
   Always-on, Маркетплейс. Медийные: Медийка.
4. **Этап «Загрузка/настройка»** считается, но не выносится в просрочки —
   это техническая задача последнего дня, а не продакшен-дедлайн.

## Связка с Заданием №1

`--models` подтягивает список моделей из креативного брифа: если под модель
готовятся креативы, но в плане её нет — агент подсвечивает дыру. Обратная
связка идёт через `plan.json`: поле `creative_id` каждой кампании ведёт
в креативный пайплайн, откуда можно запускать генерацию под нужный формат.

## Структура

```
contentplan/
  loader.py        чтение Excel, парсинг правил и порогов из самого файла
  deadlines.py     обратный отсчёт, перенос выходных
  checks.py        11 проверок, каждая — отдельная функция
  report.py        отчёт проверок и недельный дайджест
  excel_out.py     запись плана с живыми формулами
  calendar_html.py интерактивный Гант со сценарием «что если»
run.py             CLI
prompts/           промпты для Claude Code (см. ниже)
```

## Промпты

Агентная часть живёт в `prompts/` и в `.claude/commands/` — это slash-команды
Claude Code:

- `/plan` — прогнать пайплайн на новом файле, объяснить расхождения человеческим
  языком и предложить, что двигать.
- `/digest` — превратить `plan.json` в короткий дайджест для менеджера.

Пайплайн при этом самодостаточен: отчёт и дайджест генерируются шаблонами и без
LLM. Claude Code добавляет поверх интерпретацию и рекомендации.
