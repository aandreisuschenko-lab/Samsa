# AI Content Plan Agent

**Тестовое задание №5 — Samsung Electronics · AI Marketing Manager**
Автоматизация мастер контент-плана Digital

Агент заменяет ручное ведение контент-плана: принимает от менеджера список
моделей с датами старта, строит полный план месяца, считает дедлайны по правилам
каждого типа кампании, находит риски срыва раньше человека и каждую неделю
говорит, что горит и что делать.

```
Вводные менеджера  →  Контент-план  →  Дедлайны  →  Проверки  →  Календарь + Дайджест
   5 строк Excel       18 кампаний     11 правил    11 проверок      Word / HTML
```

---

## Быстрый старт

```bash
pip3 install openpyxl python-docx

# Шаг 1 — построить план из вводных и сразу прогнать пайплайн
python3 build_plan.py data/plan-input.xlsx --run

# Шаг 2 — прогон по существующему плану (ведение и трекинг)
python3 run.py data/samsung-digital-content-plan-template.xlsx \
               --models data/samsung-creative-brief-template.xlsx \
               --today 2026-07-01
```

Всё. Результаты — в папке `out/`.

> `python-docx` — мягкая зависимость. Если её нет, пайплайн не падает: отчёты
> сохраняются в markdown, а в консоль выводится подсказка по установке.

## Что решает

Каждый месяц Samsung ведёт десятки digital-активностей: промо-запуски,
always-on, медийка, поддержка дистрибьюторов, маркетплейсы. Под каждую — свой
креатив, свои дедлайны, своя точка назначения. Всё живёт в ручной таблице:
менеджер сам считает сроки, сам следит за креативами, сам вспоминает, какой
дистрибьютор давно без поддержки. **Ошибка в одной дате — сорванный запуск,
простой бюджета и потерянные продажи.**

Агент закрывает весь цикл: планирование → расчёт → контроль → еженедельный
трекинг.

## Найденная ошибка в исходном плане

> В приложенном файле дедлайны посчитаны единым правилом **−14 / −7 / −3** для
> всех кампаний, хотя на вкладке «Правила дедлайнов» они отличаются по типам.

Агент находит расхождения и показывает последствия. Ошибка оказалась системной —
она затрагивает **8 из 12 кампаний** и разошлась по четырём типам:

| Тип | Кампании | Что не так | Последствие |
|---|---|---|---|
| **Медийка** | C-06, C-09 | брифу нужен −21 день, стояло −14 | **критично:** оба брифа просрочены, видеопродакшен физически не успевает к старту |
| **Маркетплейс** | C-03, C-08 | цикл короче: −10 / −5 / −3 | ложная срочность, ресурс студии тратится раньше нужного |
| **Always-on** | C-10, C-12 | цикл короче: −10 / −5 / −3 | то же |
| **Retail support** | C-04, C-05, C-11 | согласование −4, а не −3 | +1 день дистрибьютору не заложен |

Сверх прямых требований задания агент нашёл ещё три дыры:

- модель **AR80F09CABWNER** есть в креативном брифе (Задание №1), но кампаний под неё в месяце нет;
- **Evrika** — единственный дистрибьютор из матрицы, на который не ведётся трафик;
- медийка на **Bespoke line** и **RB53DG703EB1WT** идёт без перформанс-поддержки — охват не сконвертируется.

## Как это работает

### Шаг 1 — построение плана из вводных

Менеджер заполняет **пять колонок** в файле формата мастер-таблицы. Остальные
тринадцать достраивает агент.

| Заполняет менеджер | Достраивает агент |
|---|---|
| Модель · Категория · Тип кампании · Старт · Приоритет | ID · Неделя · Канал · Назначение · Креатив ID · Формат · три дедлайна · Финиш · Бюджет · KPI · Ответственный · Статус |

Обязательны только **Модель** и **Старт** — дата задаётся отдельно для каждой
модели.

```bash
python3 build_plan.py --template          # получить пустой файл вводных
python3 build_plan.py data/plan-input.xlsx --run
```

**Логика разнесения** опирается на матрицу «3. Каналы и назначения»:

| Приоритет | Что получает модель |
|---|---|
| **A** — герой месяца | два перформанс-канала + маркетплейс + дистрибьютор + медийка |
| **B** | перформанс + маркетплейс + дистрибьютор |
| **C** | минимум по правилу вкладки 3: перформанс + точка продаж |

Тип кампании выводится из вводных: есть промо-цена → Промо-запуск, нет →
Always-on; трафик на Kaspi/Ozon → Маркетплейс, на ритейлера → Retail support.
Форматы креативов берутся из колонки «Нужные форматы» матрицы, дистрибьюторы
распределяются по кругу, чтобы никто не остался без поддержки.

Два правила вкладки 3 обеспечиваются **по построению**, а не отлавливаются
проверкой постфактум:
- одна модель за месяц закрывает минимум 1 перформанс-канал + 1 точку продаж;
- медийка ставится только поверх перформанс-канала.

Если на неделю набирается больше 4 запусков, агент двигает наименее критичные
кампании вперёд и печатает отчёт, что и куда переехало. Перформанс-ядро и
медийка двигаются в последнюю очередь.

**Ручной контроль там, где он нужен.** Если менеджер сам заполнил Канал и
Назначение в строке, агент уважает выбор: строит ровно эту кампанию и ничего не
добавляет от себя. Автоматика и ручные решения смешиваются в одном файле.

### Шаг 2 — расчёт дедлайнов

Обратный отсчёт от даты старта по правилам **своего типа** кампании. Дедлайн,
выпавший на выходной, переносится на предыдущий рабочий день.

В Excel это записывается формулой, а не значением:

```
=WORKDAY(Старт − N + 1; −1)
```

Формула возвращает сам день, если он рабочий, и предыдущую пятницу, если он
выпал на субботу или воскресенье. **Менеджер меняет дату старта — дедлайны
пересчитываются внутри файла, без запуска кода.**

### Шаг 3 — проверки

| Код | Приоритет | Что ловит |
|---|---|---|
| `RULE_MISMATCH` | P1 / P2 | дедлайны, посчитанные не по правилам своего типа |
| `OVERDUE` | P1 | дедлайн в прошлом при статусе ≠ Готово |
| `INFEASIBLE` | P1 | до старта меньше времени, чем требует цикл производства |
| `NO_CREATIVE` | P1 | старт менее чем через 7 дней, креатив не готов |
| `WEEK_OVERLOAD` | P2 | больше 4 запусков на неделю |
| `DEADLINE_CRUNCH` | P2 | больше 6 дедлайнов на ближайшие 7 дней |
| `MEDIA_NO_PERF` | P2 | медийка на модель без перформанс-поддержки |
| `MODEL_GAP` | P2 | модель из креативного брифа без кампаний в месяце |
| `DISTRIBUTOR_GAP` | P3 | дистрибьютор из матрицы без поддержки |
| `CHANNEL_UNKNOWN` | P3 | канал вне матрицы — форматы креативов не определены |
| `BUDGET_BALANCE` | P3 | доля медийки выше порога |
| `NO_SALES_POINT` | P3 | модель без маркетплейса и дистрибьютора |

**P1** — запуск под угрозой срыва, реакция нужна сегодня.
**P2** — риск не успеть или потерять эффективность.
**P3** — недоработка плана: дыры в покрытии, дисбаланс.

## Архитектурные решения

**Расчёты делает детерминированный Python, не языковая модель.** Дедлайны,
проверки и перенос выходных — арифметика, где LLM только добавила бы риск
ошибки. Модель подключается там, где нужна интерпретация: объяснить расхождения
человеческим языком и предложить конкретные сдвиги.

**Правила не захардкожены.** Циклы продакшена читаются со вкладки «2. Правила
дедлайнов», пороги тревоги — со вкладки «4. Трекинг», матрица каналов — со
вкладки «3. Каналы и назначения». Поменяет маркетинг цикл продакшена — код не
трогаем. Неизвестный тип кампании → берётся самый консервативный набор правил,
чтобы агент не занизил сроки.

**Дедлайны в Excel — формулы, а не значения.** План остаётся живым инструментом
менеджера, а не разовой выгрузкой.

**Минимум зависимостей.** `openpyxl` и мягкий `python-docx` — чтобы проверяющий
запустил проект без настройки окружения.

```
build_plan.py              шаг 1: строит план из вводных менеджера
run.py                     шаг 2: дедлайны, проверки, календарь, дайджест
contentplan/
  planbuilder.py           разнесение по каналам, выравнивание недель
  loader.py                чтение Excel, парсинг правил и порогов из файла
  deadlines.py             обратный отсчёт, перенос выходных
  checks.py                11 проверок, каждая — отдельная функция
  report.py                markdown-версия отчёта и дайджеста (fallback)
  report_docx.py           отчёт проверок и дайджест в Word
  excel_out.py             запись плана с живыми формулами
  calendar_html.py         интерактивный Гант со сценарием «что если»
data/                      входные Excel
out/                       результаты (генерируются, руками не править)
prompts/, .claude/commands/  промпты и slash-команды Claude Code
CLAUDE.md                  контекст проекта для AI-ассистента
```

## Запуск через AI-агента

Пайплайн самодостаточен и работает без всякого AI. Поверх него — агентный слой
для тех, кто не хочет открывать терминал.

**Claude Code.** Запустить `claude` в папке проекта, затем:

| Команда | Что делает |
|---|---|
| `/plan` | июльский файл, дата расчёта 01.07.2026 по умолчанию |
| `/plan data/plan-august.xlsx` | другой файл, дата по умолчанию |
| `/plan data/plan-august.xlsx 2026-07-13` | файл и дата расчёта |
| `/digest` | короткая сводка из `out/plan.json` |

Команды разбирают аргументы по формату, а не по позиции — порядок не важен.

**Claude Cowork.** Дать доступ к папке проекта и писать задачи словами:
«построй план по вводным и покажи риски», «пересчитай на сегодня и дай дайджест».
Файл `CLAUDE.md` в корне подхватывается автоматически — контекст проекта не
нужно объяснять заново.

## Допущения

1. **«+1 день на согласование с дистрибьютором».** В таблице правил этот день уже
   зашит в тип Retail support (−4 против −3 у промо). Для кампаний других типов,
   ведущих на дистрибьютора, агент добавляет его сам — иначе правило не работает.
2. **Дистрибьюторы** определяются как назначения из матрицы за вычетом samsung.kz
   и маркетплейсов (Kaspi, Ozon).
3. **Перформанс-типы** для правила «медийка только с поддержкой»: Промо-запуск,
   Always-on, Маркетплейс. Медийные: Медийка.
4. **Этап «Загрузка/настройка»** считается, но не выносится в просрочки — это
   техническая задача последнего дня, а не продакшен-дедлайн.
5. **Правила разнесения по приоритетам A/B/C** заданы в коде: в исходных файлах
   их нет, задание описывает только матрицу «канал → назначение → формат». Все
   собраны в одном месте — `contentplan/planbuilder.py`.

## Что дальше

- **Мощность студии как ограничение.** Сейчас агент выравнивает недели по числу
  запусков. Следующий шаг — считать не кампании, а креативы: сколько макетов
  студия реально успевает в неделю, с учётом того, что видео дороже баннера.
- **Напоминания ответственным.** У каждой кампании есть владелец и дедлайны —
  этого достаточно, чтобы рассылать персональные письма за N дней до срока.
- **Автозапуск генерации креативов.** Поле `creative_id` связывает план с
  пайплайном Задания №1: дайджест может не только сообщать «CR-012 не начат»,
  но и запускать генерацию под нужный формат.
- **История прогонов.** Накапливая `plan.json` по месяцам, можно увидеть, какие
  типы кампаний систематически срываются, и скорректировать сами правила
  дедлайнов — то есть замкнуть контур обучения на данных.
