# Контекст проекта для AI-ассистента

Этот файл читается автоматически при работе в папке проекта. Здесь — всё, что
нужно знать, чтобы помогать без дополнительных объяснений.

## Что это за проект

Решение **тестового задания №5 для Samsung Electronics** на позицию AI Marketing
Manager: «Автоматизация мастер контент-плана Digital». Сдача — репозиторий,
README, использованные промпты, готовые артефакты и офлайн-презентация с живым
демо.

Пользователь — digital-менеджер из Алматы, работает с медиапланированием и
кампанийной аналитикой. Работает на macOS, **только `python3`, команды `python`
на этой машине нет**. Общение на русском.

## Бизнес-задача из ТЗ

Samsung ведёт десятки digital-активностей в месяц (промо-запуски, always-on,
медийка, поддержка дистрибьюторов, маркетплейсы). Всё в ручной таблице:
менеджер сам считает дедлайны, сам следит за креативами, сам вспоминает, какой
дистрибьютор без поддержки. Нужен агент, который ведёт план за менеджера.

Сценарий из ТЗ:
1. Менеджер загружает список моделей, промо и планируемых дат старта.
2. Агент строит полный план: разносит кампании по каналам и назначениям,
   подбирает форматы креативов.
3. Считает дедлайны обратным отсчётом **по правилам своего типа кампании**.
4. Находит конфликты: просрочки, перегруз недели, кампании без креатива, дыры
   в покрытии.
5. Выдаёт еженедельный дайджест: что горит, что делать, где дыры.
6. План обновляется при смене дат без ручного пересчёта.

Отдельным пунктом ТЗ: **в исходном файле дедлайны посчитаны единым правилом
−14 / −7 / −3**, хотя на вкладке «Правила дедлайнов» они отличаются по типам.
Агент обязан найти эти расхождения и показать, какие кампании под риском.

## Архитектурные решения (объяснять на защите именно так)

- **Расчёты делает детерминированный Python, не LLM.** Дедлайны, проверки,
  перенос выходных — арифметика, где модель только добавила бы риск ошибки.
  LLM подключается для интерпретации: объяснить расхождения и предложить сдвиги.
- **Правила не захардкожены.** Циклы продакшена читаются со вкладки «2. Правила
  дедлайнов», пороги тревоги — со вкладки «4. Трекинг», матрица каналов — со
  вкладки «3. Каналы и назначения». Поменяет маркетинг цикл — код не трогаем.
- **Дедлайны в Excel пишутся формулами** `=WORKDAY(старт−N+1;−1)`, а не
  значениями: менеджер меняет дату старта — всё пересчитывается внутри файла.
  Эта формула возвращает сам день, если он рабочий, и предыдущую пятницу, если
  он выпал на выходные.
- **Две зависимости: openpyxl и python-docx.** Вторая мягкая: если её нет,
  отчёты сохраняются в markdown, пайплайн не падает.
- **Отчёт проверок и дайджест отдаются в Word (.docx)**, не в markdown —
  так их можно сразу переслать руководителю.

## Структура

```
build_plan.py              шаг 1: строит план из вводных менеджера
run.py                     шаг 2: дедлайны, проверки, календарь, дайджест
contentplan/
  planbuilder.py           разнесение по каналам, выравнивание недель
  loader.py                чтение Excel, парсинг правил и порогов из файла
  deadlines.py             обратный отсчёт, перенос выходных
  checks.py                11 проверок, каждая — отдельная функция
  report.py                отчёт проверок и недельный дайджест
  excel_out.py             запись плана с живыми формулами
  calendar_html.py         интерактивный Гант со сценарием «что если»
data/                      входные Excel
out/                       результаты (ГЕНЕРИРУЕМЫЕ — руками не править)
prompts/, .claude/commands/  промпты и slash-команды
```

## Команды

```bash
# построить план из вводных и сразу прогнать пайплайн
python3 build_plan.py data/plan-input.xlsx --run

# создать пустой шаблон вводных
python3 build_plan.py --template

# прогон по готовому плану
python3 run.py <файл.xlsx> --models data/samsung-creative-brief-template.xlsx --today YYYY-MM-DD

# демо-набор для защиты (эталонные цифры: 12 кампаний, 21 проблема — 8 P1, 11 P2, 2 P3)
python3 run.py data/samsung-digital-content-plan-template.xlsx --models data/samsung-creative-brief-template.xlsx --today 2026-07-01
```

Slash-команды в Claude Code: `/plan` (пересчёт + разбор), `/digest` (сводка).

## Важные правила работы

- **Файлы в `out/` только генерируются.** Никогда не редактировать их руками:
  репозиторий разойдётся с тем, что реально выдаёт код, и это вскроется при
  первом же запуске у проверяющего. Нужно изменить результат — меняем код или
  входной Excel и перезапускаем.
- **Везде `python3`**, не `python`.
- Основной демо-набор в `out/` всегда должен соответствовать июльскому файлу с
  датой расчёта 2026-07-01. Прогоны по другим файлам — в отдельные папки
  (`--out out-august` и т.п.).
- Не менять логику расчётов без явной просьбы: цифры уже проверены и вошли в
  презентацию.

## Что уже найдено пайплайном (эталон для сверки)

Расхождения с исходным файлом по типам:
- **Медийка (C-06, C-09)** — брифу нужен −21 день, стояло −14. Оба брифа
  просрочены, видеопродакшен физически не успевает. Это системная и самая
  критичная находка.
- **Маркетплейс (C-03, C-08)** и **Always-on (C-10, C-12)** — цикл короче
  стандартного, дедлайны стояли раньше нужного (ложная срочность).
- **Retail support (C-04, C-05, C-11)** — согласование −4 дня вместо −3.

Сверх прямых требований ТЗ: модель AR80F09CABWNER есть в креативном брифе
Задания №1, но кампаний под неё нет; Evrika — единственный дистрибьютор без
поддержки; медийка на Bespoke line и RB53DG703EB1WT идёт без перформанс-канала.

Обязательная часть ТЗ закрыта полностью. Закрытые бонусы: интерактивный
календарь, сценарий «что если», связка с Заданием №1 через `--models` и

ответственным по дедлайнам.

Осталось по проекту: репетиция демо и, опционально, веб-интерфейс на Streamlit,
чтобы пользоваться без терминала. Параллельно идёт **Задание №1** — генерация

HTML/CSS + Playwright для рендера и Photopea для сборки PSD, поскольку
Photoshop локально не установлен.
